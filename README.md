# 刃研社-产品投资决策审查（product-investment-review）

仓库 <https://github.com/firehuzi/scalpel-product-investment-review> · 许可 [MIT](LICENSE)

> **命名说明**：正式名称是「刃研社-产品投资决策审查」。GitHub 的仓库名只允许 ASCII 字母、数字与 `. - _`——
> 表单会直接把「刃研社」剥掉——所以 slug 用 `scalpel-product-investment-review`（与 `scalpel-downloadx` 同一套命名）。
> 技能标识符保持 `product-investment-review`，改它会让你已安装的那份对不上。

一个**审查产品 Idea / 任务书 / 项目提案**的 Agent Skill。

它不是产品共创助手，是 **Independent Investment Committee**：

> 不是问「怎么让这个 idea 变得更好」，而是问「为什么它可能不值得做」。
> **它要比你自己更愿意杀掉你的 idea。**

输出不是评分，是**投资决策**：四档 verdict + Next Investment（下一笔资源投多少、投在哪、验证什么、门槛在哪、达不到怎么退）。

---

## 它凭什么不是又一个「AI 帮你评估想法」

| 机制 | 为什么它改变结论 |
| --- | --- |
| **拒绝任何分数** | 不许出现「Founder Fit 3/4」「置信度 75%」——分数制造虚假精确度，是这类审查最容易复发的病。只给四档 verdict + 定性证据强度 |
| **Step 0 强制读你自己的决策日志** | 通用模型能告诉你「这类项目通常死在哪」（常识，免费给）；**只有你的历史能告诉你「你这类项目每次死在哪」**（镜子，只有本地能建） |
| **10 类错位检查表** | 框架 vs 信息 / 否定者 vs 选择者 / 需求错配 / 冷启动悖论 / 输出层 vs 数据层 / 假进展 / 矩阵幻觉 / 收集即奖励 / 资产态加速 / 样本幻觉 |
| **抗吞噬测试** | 「如果这个能力明天被模型原生支持，这个产品还剩什么？」价值与模型能力成反比的，生命周期等于一次版本更新 |
| **逃避检测** | 识别「用开发逃避不确定性」：能靠 5 次对话回答的问题，不要用 8–16 小时的 MVP 去验证 |
| **Tranche 而非 Round** | 不用「通过 → 进入下一轮」（那会推向承诺升级），用「这笔花完 → 回到 Step 0 重新申请」 |
| **预登记预测** | 写下的那一刻登记可证伪、带数值、带检查日期的预测。事后归因偏差下，只有原始文本能对抗「我早就知道」 |

它对**自己**也用过一次：判定「精致但无效——被使用了，但没有改变任何一个决定」，并给自己下了 60 天冻结令（冻结期内不许再改检查表、不许登记新预测，只准把已有的 Outcome 填完）。
这条自我判决保留在本仓库的设计逻辑里：**一个方法论如果不能被自己的使用者执行，继续改进它只是在改进一件没人穿的衣服。**

## 安装

把整个目录放进你的 Agent 的 skill 目录：

```text
~/.codex/skills/product-investment-review/          # Codex
~/.claude/skills/product-investment-review/         # Claude Code
<你的工作台>/.workbuddy/skills/product-investment-review/   # WorkBuddy 一类本地工作台
```

## 用法

拿一个 idea、一份任务书、一个项目提案问它就行：

> 「这个方向值不值得做？」
> 「帮我看看这个产品有没有戏。」
> 「我有个 idea……」

它会依次走：读历史（Step 0）→ 四问审查 → 十类错位 → 抗吞噬 → Bull Case → Bear Case + 最强反例 → Critical Unknowns → 对抗性复审（可选）→ Verdict → Next Investment → 写入 Decision Ledger。

**第一次使用时 Ledger 是空的**，它会明说「无历史基线，本次无法做历史拦截」。这个工具的价值随你自己的档案增长——**它不复制你的历史，它读取你的历史。**

## 仓库内容

```text
product-investment-review/
├── SKILL.md                       # 入口：身份、硬性约束、Step 0–9、输出格式
├── references/anti-patterns.md    # 检查表正文：10 类错位 + 判定标准 + 强制动作
└── memory/decision-log.md         # Decision Ledger 格式（只留规范，条目由你自己积累）
```

> **关于案例数据**：本仓库的 `anti-patterns.md` 保留了全部检查项、判定标准与机制，
> 但其中来自真实项目组合的「本例证据」已**脱敏**——项目名替换为 `项目 A/B/C…`，
> 绝对内部指标替换为相对变化。Decision Ledger 只发布格式模板。
> 也就是说：**你拿到的是方法，不是别人的档案。**

## 已知问题（故意不修）

- `SKILL.md` 的 Step 2 仍写「**五类**错位」，而 `references/anti-patterns.md` 已经长到编号 1–11（共 12 节，「**错位 10**」出现了两次）；1–6 用 `##` 标题、7–11 用 `#` 标题，层级不一致。
- 为什么这个仓库不顺手修掉它：这套工具给自己下过一条冻结令——在被自己的历史证明「**没有改变过任何一个决定**」之后，**不许再精修它**，只准把已有的 Outcome 填完。计数与编号属于它自己的待办，不属于发布者可以代劳的编辑。
- 留下这条缺陷是有意的：它让「检查表自己也需要被检查」这件事，跟检查表放在同一个页面上。
- 另外，`SKILL.md` 的 frontmatter 带一个非标准键 `agent_created: true`（本机工作台需要它）。
  Codex 自带的 `quick_validate.py` 会提示它不属于允许字段，但技能本身能正常加载；
  严格的 linter 报这条属于预期，**不要为此改动原始文件**。
