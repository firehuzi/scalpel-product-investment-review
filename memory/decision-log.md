# Decision Log

> 本文件是 `product-investment-review` 的历史档案，也是它**唯一的不可复制资产**。
> 模型有通用推理能力，但它不拥有你的历史——这个文件的全部意义就在这里。
>
> **规则：只追加，不修改历史条目。** 判断错了也要留着，错判比正确判断更有校准价值。

## 条目格式（Decision Ledger）

> 一条记录不是「做了什么决定」，而是完整的
> **Decision → Hypothesis → Evidence → Investment → Gate → Outcome → Prediction Error**。
> 其中 **Prediction 必须在写下的那一刻登记**，事后不得修改——
> 没有预登记的预测，事后永远能被解释成「我早就知道」。

```markdown
### YYYY-MM-DD | <项目名>

**Decision**
- Verdict: 🟢 / 🟡 / 🔵 / 🔴
- 一句话理由:
- Founder Fit: 明显优势 / 明显缺口 / 致命缺口 / 尚未验证项
  （逐项列能力 + 证据强度：真实资产 / 弱证据 / 未知 / 无证据——**不给分数**）

**Hypothesis**
- 成立所依赖的核心假设（哪一条错了，整个项目就不成立）

**Investment**
- 本轮批准: X 小时 / Y 元（硬上限）
- 投在哪里:
- Gate: 达到什么标准算通过（可判定）
- Kill Line: 达不到 → 退回哪一步 / 杀掉（预先声明，事后不得改口）

**Prediction**（登记于写下时，事后不得修改）
- 到 YYYY-MM-DD，<具体可判定的结果>
- 若未出现 → 本次判断记为错误，并写明错在哪一格

**Outcome**（重跑时填，仅追加）
- 实际结果:
- Prediction Error: 命中 / 未命中（**未命中更有价值**）
- 判断对了吗: 对在哪一格 / 错在哪一格
- 这次学到什么:
- 死亡/停滞位置: 验证前 / 第二个功能 / 上线后无人用 / 从未上线 / —
```

- **Verdict**: 🔵 **RESEARCH / TEST**（提案方自评 🟡 CONDITIONAL INVEST，审查方下调一档）
- **一句话理由**:
  打算花 8–16 小时去验证一个 5 次对话就能验证完的假设。一个专门防止「过早开发」的工具，
  自己的第一笔投资就是过早开发。
- **Founder Fit**:（原形态四项所需能力中仅一项为真实资产 —— 早期记为 1/4，**本 Ledger 不打分**）

    竞品与市场数据抓取工程（是工程活，非其壁垒）

  不是**框架**（自己写得出来）。**若最缺的是框架 → 整个项目不成立**（框架免费且人人可写）。
- **投入**: 2–4 小时，**零代码**（硬上限）
- **投在哪里**: 三次零代码测试（对话 / 提问 / 小实验）——**不是 MVP**
- **验证什么**:
  - U1 开发者判断时最缺的是**框架**还是**信息**？
  - U2 付费动机是「请否定我」还是「帮我选 / 帮我解释」？
  - U3 与「ChatGPT + 500 字投资人 prompt」相比，增量价值多大、值多少钱？
- **Gate**（三条同时达标才允许投入开发）:
  1. Test 1 中 ≥3/5 的痛感出现在**决策当下**（非事后）
  2. Test 2 中 ≥3/5 最缺的是**信息**
  3. Test 3 中 ≥2/5 报出**非零价格**
- **Kill Line**: 任一条不达标 → **不做产品**，本方法论保持为自用 skill，记 🔴 PASS
- **重跑日期**: 2026-09-28
- **Prediction**（登记于 2026-08-28，事后不得修改）:
  1. 到 2026-09-28，本 skill 是否被用于审查 **≥3 个真实项目**
     （不含它自己、不含它自己的升级版）？**<3 → 记未命中**。
  2. 到 2026-09-28，三次审查中是否有 **≥1 次实际改变了一个原本要做 / 不做的决定**？
     **0 次 → 记未命中**，说明它只是让决策看起来更严谨，没有改变决策。
  3. 若 1 和 2 都未命中 → 判定为「方法论自洽但未生效」，下一轮下调至 🔴 PASS。
- **备注（本次审查的形态演进，留档供后续比对）**:

- **为什么否决 Round 制（本轮最重要的判定）**:
  Round 制是 VC 的真实结构（外部资本分批注入 + 沉没成本的信号效应），
  它的**默认动作是「通过 → 进入下一轮」**，会把项目推向承诺升级。
  而本档案第一条已经记着：**他的项目不是死在验证，是死在第二个功能。**
  → **Round 制恰恰会让他更顺滑地走到第二个功能。**
  且这是「隐喻反客为主」的**第二次发生**（第一次是漏斗）。
  同一隐喻（VC）反复出现 = 它被当成了本体，而不是工具。

- **⚠️ 偏误信号（第 2 次，同一格）**:
  用户在 v7 复审中给本 skill 自身打出 **🟢 INVEST**，理由为「已出现清晰的不可复制机制」。
  依硬性约束 6，这属于**无新证据上调**——尚未跑满 3 个真实项目，机制存在 ≠ 价值已被验证。
  **判定：维持 🔵 RESEARCH/TEST。**
  与第一次（01 从 🔵 上调 🟡 无新证据）发生在**同一格**：
  **自我评价自己的方法论。**
  → **这是该用户已确认的第一个偏误模式，Step 0 的《偏误基线》必须优先检查这一格。**

- **本次审查自身的方法论沉淀**:
  > **不要问「怎么做一个不会被 AI 替代的工具」，要问「怎么做会随着 AI 进步而变强的工具」。**
  > 答案不是躲开 AI，是站在 AI 拿不到的东西上——**你的历史**。
  >
  > **一个方法论最大的风险不是被别人否定，是被自己人放行。**
  > 框架越自洽，越容易给自己打高分——**自洽不是有效。**
